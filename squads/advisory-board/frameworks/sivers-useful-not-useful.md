# Sivers Useful Not Useful

## Purpose

Derek Sivers replaces the typical "right/wrong" or "agree/disagree" evaluation with a simpler, more productive filter: "Is this useful?" This framework removes the ego and ideology from evaluation and focuses purely on practical value. An idea, framework, or piece of advice doesn't need to be "true" in an absolute sense — it just needs to be useful for the situation at hand.

## When to Use

- When evaluating advice, frameworks, or mental models
- When team members are debating ideology instead of solving problems
- When a "wrong" idea actually contains useful elements
- When feedback is being rejected because of its source rather than its content
- When perfectionism is preventing progress (a useful-enough solution beats a perfect one)

## Core Model

### The Binary
Every piece of information, advice, or framework gets evaluated on one axis:
- **Useful:** It helps me make better decisions, take better action, or understand something more clearly → Adopt it
- **Not Useful:** It doesn't help with any of the above → Set it aside

### Why This Beats "True/False"
- Multiple conflicting frameworks can all be useful in different situations
- An imperfect framework that produces better decisions is more valuable than a perfect theory with no practical application
- Evaluating usefulness bypasses ideological arguments and ego attachment
- It encourages intellectual humility: "I don't need to decide if this is universally true; I just need to decide if it's useful for me right now"

### The Pragmatic Hierarchy
1. **Useful and true:** Best case. Apply with confidence.
2. **Useful but imperfect:** Still valuable. Apply while acknowledging limitations.
3. **True but not useful:** Intellectually interesting but doesn't change behavior. Deprioritize.
4. **Neither useful nor true:** Discard.

## Steps

1. **When receiving any input** (advice, framework, data, feedback), ask: "Is this useful for my current situation?"
2. **If useful**, adopt it regardless of whether you agree with the source or the broader theory.
3. **If not useful**, set it aside without judgment. It may be useful later or to someone else.
4. **Apply this to your own ideas.** Are you pursuing an idea because it's useful or because you're attached to it?
5. **Teach your team this filter.** It reduces unproductive debates and accelerates decision-making.

## Application Guidelines

### For Board Advisors
- When multiple advisors give conflicting advice, help the founder evaluate each on usefulness rather than trying to determine who is "right."
- Apply this to frameworks themselves: not every framework in this collection will be useful for every situation. Use what works, set aside what doesn't.

## Common Mistakes

1. **Rejecting useful input because of the source.** Useful ideas can come from unlikely places.
2. **Keeping useless ideas because they're intellectually elegant.** Pretty theories with no practical value are decoration.
3. **Confusing "uncomfortable" with "not useful."** The most useful feedback is often the most uncomfortable.

## Output Format

```markdown
# Usefulness Filter: [Input Being Evaluated]

- Source: [Where it came from]
- Claim/Advice: [What was said]
- Useful for current situation? [Yes/No]
- If yes, how to apply: [Specific action]
- If no, reason: [Why not useful now]
```
