# Workflow Guide

## Purpose

This guide helps you select and execute the right workflow for any board activity. Every workflow is a complete, end-to-end playbook — follow it step by step.

## How to Read a Workflow

Every workflow contains the same sections:

1. **Overview:** What the workflow does and when to use it.
2. **Trigger:** The specific event or condition that initiates the workflow.
3. **Agents:** Which agents are involved and their roles.
4. **Phases:** The step-by-step process, numbered and ordered.
5. **Quality Gates:** Checkpoints that must be passed before proceeding.
6. **Outputs:** What the workflow produces.
7. **Timeline:** Expected duration and key milestones.
8. **Metrics:** How to measure whether the workflow was executed well.
9. **Common Failures:** What typically goes wrong and how to prevent it.

## How to Execute a Workflow

1. **Identify the trigger.** Make sure the workflow is appropriate for your situation.
2. **Assign agents.** Confirm which agents are needed and that they are available.
3. **Follow the phases in order.** Don't skip steps. Each phase builds on the previous one.
4. **Pass quality gates.** Before moving to the next phase, verify the gate criteria are met.
5. **Produce the outputs.** Each workflow has defined deliverables. Create them.
6. **Measure.** After completion, assess against the workflow's metrics.
7. **Archive.** Store all artifacts in the appropriate archive location.

## Customization

Workflows are designed to be followed as written. If your situation requires modification:

1. Document the modification and the reason.
2. Get Board-Chair approval.
3. Execute the modified workflow.
4. In the retrospective, assess whether the modification should become permanent.

Modifications are recorded in `docs/changelog.md`.
