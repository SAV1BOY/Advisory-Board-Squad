# Dalio Machine Check Checklist

## Purpose
Evaluates whether the organization is functioning as a well-designed machine that produces intended outcomes, or whether it has drifted into a state of ad-hoc operation where results depend on luck and individual heroics. Dalio conceives of an organization as a machine with inputs (people, capital, strategy) and outputs (results). When outputs are unsatisfactory, the machine needs to be diagnosed and repaired. This checklist provides the diagnostic framework.

## When to Use
- Quarterly when reviewing operational performance against plan.
- When results consistently miss targets without clear explanation.
- When the organization feels chaotic despite good strategy and talented people.
- During leadership transitions where operating understanding needs to be transferred.
- When scaling demands that the machine handle increased throughput.

## Gate Criteria

### Machine Design
- [ ] **Pass/Fail**: The organization's operating model is documented: how strategy becomes execution becomes results.
- [ ] **Pass/Fail**: Key processes map to specific outcomes with measurable throughput.
- [ ] **Pass/Fail**: Roles and responsibilities are defined in terms of machine function, not just job descriptions.
- [ ] **Pass/Fail**: Interfaces between teams (handoffs, data flows, decision escalations) are defined.
- [ ] **Pass/Fail**: The design is appropriate for the current stage and scale of the business.

### Machine Performance
- [ ] **Pass/Fail**: Key performance indicators are defined for each major process.
- [ ] **Pass/Fail**: Actual performance is measured against designed performance regularly.
- [ ] **Pass/Fail**: Variances from expected performance are diagnosed promptly.
- [ ] **Pass/Fail**: Bottlenecks and constraints are identified and prioritized for resolution.
- [ ] **Pass/Fail**: Throughput capacity is known and matched to demand.

### People in the Machine
- [ ] **Pass/Fail**: Each role's contribution to the machine's output is clear to the person in the role.
- [ ] **Pass/Fail**: People are matched to roles based on demonstrated capability for that specific function.
- [ ] **Pass/Fail**: Underperformance in a role is diagnosed as a people issue, a training issue, or a design issue.
- [ ] **Pass/Fail**: The machine does not break when any single individual is absent.

### Machine Maintenance
- [ ] **Pass/Fail**: Regular reviews assess whether the machine design still fits the current context.
- [ ] **Pass/Fail**: Improvement ideas are collected, evaluated, and implemented systematically.
- [ ] **Pass/Fail**: Technical debt in processes, tools, and documentation is tracked and managed.
- [ ] **Pass/Fail**: The machine is stress-tested: what happens at 2x current volume.

## Red Flags
- Results depend on a few heroes working unsustainable hours.
- No one can explain the end-to-end process for the company's most critical workflows.
- Similar work is done differently by different teams with no standard.
- The machine breaks visibly when any key person takes a vacation.
- Leadership discusses strategy and people but never discusses the operating machine itself.
- Error rates and rework are high but accepted as normal.

## Escalation Triggers
- The machine produces a critical failure that was foreseeable from known design flaws.
- Throughput capacity cannot meet demand and no scaling plan exists.
- A regulatory or audit finding reveals the machine lacks controls for a required function.
- Multiple teams independently develop workarounds for the same machine failure.
- The machine's design has not been reviewed since the company was half its current size.
