# Decision Memo Framework

## Purpose

The Decision Memo Framework provides a structured, one-page format for documenting critical decisions. It forces clarity by requiring decision-makers to articulate the problem, enumerate options, weigh trade-offs, and commit to a path forward — all in a concise, reviewable document. This framework eliminates the ambiguity that plagues organizational decision-making and creates an auditable trail of reasoning.

## When to Use

- Before any significant resource allocation (budget, headcount, time)
- When multiple stakeholders need to align on a single course of action
- For decisions that will be difficult or expensive to reverse
- When you need to communicate a decision to people who were not in the room
- During board meetings when formal documentation of reasoning is required
- Any time you catch yourself saying "we should probably..." without writing it down

## Core Model

The Decision Memo follows a strict four-part structure:

### 1. Problem Statement
A crisp, falsifiable statement of what needs to be decided and why now. The problem statement must answer:
- What is the decision to be made?
- Why does this decision matter?
- What is the cost of inaction or delay?
- Who is the decision-maker (single person, not a committee)?

### 2. Options
A minimum of three options, including the status quo. Each option includes:
- **Description**: What this option entails in concrete terms
- **Resource requirements**: Time, money, people, attention
- **Timeline**: When this option would deliver results
- **Confidence level**: How confident are we in our ability to execute?

### 3. Trade-offs
An honest assessment of what you gain and lose with each option:
- **Upside**: Best realistic outcome
- **Downside**: Worst realistic outcome
- **Hidden costs**: Second-order effects, opportunity costs, organizational drag
- **Reversibility**: Can we undo this? At what cost?

### 4. Decision
The chosen path with clear rationale:
- **Decision**: One sentence stating the choice
- **Rationale**: Why this option over others (2-3 sentences)
- **Dissent**: What the strongest counterargument is
- **Review trigger**: What would cause us to revisit this decision

## Steps

1. **Draft the problem statement** in one paragraph. If you cannot state the problem in one paragraph, you do not yet understand it well enough to decide.

2. **Generate at least three options.** Force yourself past the binary. "Do it or don't" is almost never the real option set. Include creative alternatives, phased approaches, and the null option.

3. **Score each option** against your key criteria. Use no more than five criteria. Weight them if some matter more than others.

4. **Write the trade-off analysis** for each option. Be brutally honest about downsides. The value of this exercise is in the honesty, not the optimism.

5. **Make the call.** Write the decision in one sentence. If you cannot state it in one sentence, the decision is not yet clear.

6. **Document dissent.** Record the strongest argument against your decision. This is not weakness — it is intellectual honesty that will help future decision-makers understand context.

7. **Set a review date.** Every decision should have a revisit trigger — either a date or a condition that would cause you to reconsider.

## Application Guidelines

### For Board Advisors
- Use this framework to structure recommendations to founders. Never present a recommendation without the full option set.
- Insist on seeing the dissent section. If there is no dissent, the analysis is incomplete.
- Push back on memos with only two options — this usually means the team has already decided and is seeking validation, not advice.

### For Founders/CEOs
- Write the memo yourself before bringing it to your board or advisors. The act of writing clarifies thinking.
- Share the memo 48 hours before the meeting where the decision will be discussed.
- After the decision, circulate the final memo to all stakeholders within 24 hours.

### For Teams
- Assign one person to write the memo. Group-written memos are reliably mediocre.
- Use the memo as the meeting agenda. Read it silently for the first 10 minutes of the meeting, then discuss.
- Keep completed memos in a decision log for institutional memory.

## Common Mistakes

1. **Burying the decision in analysis.** The decision should be the first thing a reader sees after the problem statement, not the last.

2. **Presenting false binaries.** "We either do X or we don't" almost always obscures better options. Force three options minimum.

3. **Omitting the null option.** "Do nothing" is always an option and often the right one. Make it explicit.

4. **Ignoring opportunity cost.** Every option competes against everything else you could do with those resources. State what you are NOT doing.

5. **Consensus-seeking language.** "We all agreed" is a red flag. Document who decided and who dissented.

6. **Missing the timeline.** A decision without a timeline is a wish. When does this get executed? When do we review?

7. **Sunk cost anchoring.** Prior investment should not appear in the trade-offs. Only future costs and benefits matter.

8. **Excessive length.** If the memo exceeds one page, the thinking is not yet clear enough. Compress ruthlessly.

## Output Format

```markdown
# Decision Memo: [Title]

**Date:** YYYY-MM-DD
**Decision Maker:** [Name]
**Status:** Draft | Final

## Problem
[One paragraph: What needs to be decided and why now]

## Options

| Criteria        | Option A: [Name]  | Option B: [Name]  | Option C: Status Quo |
|-----------------|--------------------|--------------------|----------------------|
| Description     |                    |                    |                      |
| Cost            |                    |                    |                      |
| Timeline        |                    |                    |                      |
| Risk            |                    |                    |                      |
| Reversibility   |                    |                    |                      |

## Trade-offs
- **Option A:** [Gains vs. losses]
- **Option B:** [Gains vs. losses]
- **Option C:** [Gains vs. losses]

## Decision
**We will:** [One sentence]

**Rationale:** [2-3 sentences]

**Strongest counterargument:** [1-2 sentences]

**Review trigger:** [Date or condition]

## Signatures
- Decision Maker: _______________
- Key Stakeholders Informed: _______________
```

## Related Frameworks

- **Reversible-Irreversible Decisions** — Use to classify the decision type before writing the memo
- **Second-Order Thinking** — Apply during the trade-off analysis to surface hidden consequences
- **Opportunity Cost Framework** — Integrate into the options section to capture what you are giving up
- **Pre-Mortem Framework** — Run before finalizing the decision to stress-test the chosen option
- **Decision Log Framework** — Store completed memos for institutional learning
- **Regret Minimization Framework** — Use as a gut-check on high-stakes, irreversible decisions
