# Hoffman Network Effects Check Checklist

## Purpose
Evaluates whether the organization benefits from genuine network effects and whether those effects are being strengthened or eroding. Hoffman views network effects as one of the most powerful moats a business can build: when each new user makes the product more valuable for all existing users. This checklist distinguishes between real network effects and commonly confused phenomena (scale effects, virality, lock-in).

## When to Use
- When claiming network effects as part of the competitive advantage thesis.
- During product strategy discussions about features that could create or strengthen network effects.
- When evaluating acquisition targets that claim network effects.
- When network metrics suggest effects may be weakening.
- During investor presentations where network effects are part of the value narrative.

## Gate Criteria

### Network Effect Identification
- [ ] **Pass/Fail**: The type of network effect is identified: direct (same-side), indirect (cross-side), data, or social.
- [ ] **Pass/Fail**: The mechanism is articulated: specifically how does a new user increase value for existing users.
- [ ] **Pass/Fail**: Network effects are distinguished from scale effects (lower costs with more users, but not more value per user).
- [ ] **Pass/Fail**: Network effects are distinguished from virality (rapid spread, which may not create value feedback loops).
- [ ] **Pass/Fail**: The network effect is quantified: what is the measured increase in value or engagement per additional user.

### Network Strength Assessment
- [ ] **Pass/Fail**: Engagement metrics improve as the network grows (not just total users, but per-user activity).
- [ ] **Pass/Fail**: Retention rates improve as the network grows.
- [ ] **Pass/Fail**: Willingness to pay increases as the network grows.
- [ ] **Pass/Fail**: The network has passed the critical mass threshold where effects are self-sustaining.
- [ ] **Pass/Fail**: Network density (connections per user) is measured and growing.

### Vulnerability Assessment
- [ ] **Pass/Fail**: Multi-homing risk is assessed: can users easily participate in competing networks simultaneously.
- [ ] **Pass/Fail**: Network clustering is analyzed: is the network one large network or many small disconnected sub-networks.
- [ ] **Pass/Fail**: The risk of negative network effects at scale is evaluated (spam, congestion, quality dilution).
- [ ] **Pass/Fail**: Competitor strategies to break or bridge the network effect are anticipated.

### Strengthening Strategy
- [ ] **Pass/Fail**: Product decisions prioritize features that strengthen network effects.
- [ ] **Pass/Fail**: Switching costs are increased through value-add features (not artificial friction).
- [ ] **Pass/Fail**: Data generated by network activity creates proprietary advantages.
- [ ] **Pass/Fail**: The organization invests in network health (quality, safety, trust), not just growth.

## Red Flags
- The company claims network effects but engagement per user does not increase with network size.
- Users can easily multi-home across competing networks without friction.
- Growth comes from acquisition spending, not from network-driven organic growth.
- The network has many users but low density of connections.
- Negative network effects are emerging (noise, spam, degraded quality) and not being addressed.
- The company conflates having many users with having network effects.

## Escalation Triggers
- Per-user engagement metrics decline despite network growth.
- A competitor launches a competing network and user migration begins.
- Network quality issues (spam, abuse, trust violations) threaten the network's value proposition.
- Multi-homing becomes prevalent, reducing the network effect's competitive value.
- The cost of maintaining network quality grows faster than network revenue.
